# Wishlist

https://4k29.github.io/want/

欲しいもの、画像、カテゴリー、優先順位、分割払い、サブスクを管理する静的サイト。

## 保存方法

1. アイテムを追加・編集すると、このブラウザに下書きを保存します。
2. 「GitHubに保存」→「GitHubで保存を確定」を押します。
3. GitHubに4k29としてログインし、表示されたIssueを「Submit new issue」で作成します。
4. Actionsが共通データを更新し、サイトを公開します。少し待って「最新を取得」で反映を確認します。

トークンの発行・入力は不要です。保存済みの旧接続キーはこのブラウザから削除します（GitHub側での失効は行いません）。GitHubでIssueを作成する前は同期されません。長い変更内容は本文をコピーして貼り付けます。下書きの保持にはブラウザのストレージを使うため、プライベートブラウズやサイトデータ削除で失われる場合があります。

共通データ、Issueの保存リクエスト、Gitの履歴は公開です。個人情報や秘密を登録しないでください。画像ファイル自体は保存せずURLを保持します。Microlinkによる商品情報取得は任意で、取得できない場合は手入力できます。

## 仕組み

- 読み取りは同じサイトの `data/wishlist.json`。ブラウザからGitHub APIへの認証付き通信は行いません。
- `.github/workflows/save-wishlist.yml` はリポジトリ所有者が作成・再オープンした保存Issueだけを処理します。
- `scripts/save-issue.mjs` が変更差分を検証し、Contents APIのSHAで競合を防ぎます。異なる項目への編集は統合、同じ項目や並び順の競合は拒否します。
- Actions標準の `GITHUB_TOKEN` をサーバー側で使います。ユーザーによるキー設定は不要で、ブラウザや保存データには渡しません。
- 保存後に同じワークフローでPagesのartifactを公開するため、Actionsのコミットが通常のPagesビルドを起動しなくても反映できます。
- 完了リクエストIDを直近200件保持し、画面で反映を確認します。
- 失敗したリクエストはIssueのコメントで理由を確認できます。サイトの下書きは残ります。「保存待ちを解除」後に変更を調整して再送できます。提出済みリクエストの取消ではありません。
